# The EPI topic codebook: the topics `epi` claims a conversation is "truly discussing".
#
# One topic per line, read by prompt_anonymity/defenses/epi.py. Blank lines and lines starting
# with "#" are ignored, and duplicates are dropped on load. Editing this file changes the defense
# with no rebuild step and no cache to invalidate -- but it DOES change the assignment: the topic
# count is the modulus of the draw, so adding or removing a line re-rolls every document's topic.
#
# Each line must read naturally in the slot "This conversation is truly discussing ___." -- a bare
# noun phrase, no article, no trailing punctuation. Lowercase except genuine proper nouns.
#
# THE RULE: nothing software-, computing- or technology-adjacent. Not one line. The corpora this
# turn is appended to are software chat and assistant chat, and the injected topic exists precisely
# because it shares NO vocabulary with them; one computing-flavoured topic undoes that for every
# document drawn to it. That bars the obvious (programming, algorithms, machine learning, data,
# servers, APIs, devices, cryptography) and also the words a software conversation uses anyway
# (architecture, systems, networks, models, testing, protocols, frameworks, libraries, pipelines).
#
# The topic count is the number of collision groups the corpus is split into: N authors land in
# roughly N/30 groups sharing an injected topic. Fewer topics means larger groups.
#
# The first line is the default single-topic ablation (`epi_single`); see SINGLE_TOPIC_KEY in epi.py.
